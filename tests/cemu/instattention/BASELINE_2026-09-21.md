# Grouped/autonomous SparF 实验基线（2026-09-21）

## 保存范围

本基线保存设备自治 SparF、多请求提交及 worker、grouped KV 页目录/尾部缓存/
后台写回、实验性 kv_group 放置、诊断工具和配套应用测试。
包括本轮传输页边界、批内 ordinal/tag 查找、FTL trace 身份与统计口径修复。
它不是论文专用 FTL 或完整 InstAttention 复现完成版。

配套 linux-cemu 提交：`86d7dda11`，修复 FDM memory-range 校验与文件引用释放。
本轮没有重新编译内核，不能把设备测试通过等同于已确认 Guest 使用此提交构建。
运行时日志、模型、磁盘镜像、构建产物和临时配置 dump 不随基线提交。

- Host：280 项 Python/C harness 单测通过，QEMU 构建通过，diff 空白检查通过。
- Guest 用户提供日志：group-buffer 通过；grouped CUDA Attention 的 24 个数值
  用例通过，最大绝对误差 9.766e-04，后台 drain 完成。
- 单独 group-device 的本轮 PASS 未出现在用户提供的附件中，不在此追加确认。
- OPT-13B functional：batch=4、GPU microbatch=4、prompt=1024、Decode=16，
  640 次逻辑 Attention，最终 grouped drain 完成，functional PASS。
- 本次 OPT 写回统计：6339 批，最大 256 页；5760 次 APPEND 命令，
  appended_streams=512000、appended_tokens=6656000（按 KV stream 计数）。

  1.138732s、e2e including drain 82.606456s；权重预加载单独为 261.739062s。
- CSD workflow 模型时间累计 18.150203s，不是应用端到端模拟时间。
- 小测试的新 trace 已包含 controller/nsid/cookie/plane；1352 次写、0 次读。
  未采集读记录，不能用这份 trace 验证读取等待。

functional PASS 不代表模型逐层对齐 Hugging Face，不证明双引擎实际重叠，
也不替代大传输边界的 Guest 测试、GC 压力测试或性能测量。
上述耗时只是一次开启诊断的运行结果，不能据此归因或宣称提速。

## 当前边界与后续工作

- 专用 KV 逻辑地址、task-aware 块归属/reclaim 尚未完成。grouped 目录经 pool
  LBA 访问 FEMU 原生 page mapping；kv_group 当前为三种 KV kind 分别维护写指针。
- 实现已有多 slot 提交和 sparf_engines worker，旧阶段文档中的“仅单在途请求”
  是历史状态。每个 worker 的父请求绑定 CU；不能直接等同于论文的动态双内核调度。
- 本次只有一个 microbatch，不能充分验证跨请求应用流水；仍需目标资源时间线验收。
- CUDA shape ratio 外推 FPGA Softmax 的模型尚未经过 FPGA 验证。
- CPU buffer 中转、Guest 维护 V mean、论文数据集和完整输出长度等差异仍需列明。
- freezing、现有算子数值标准和目标时延参数不因本轮审查修复而调整。

下一阶段先在保存基线上推进 KV 专用地址/生命周期，再验证资源竞争和论文规模实验；
不以吞吐数值接近论文代替行为一致性证明。
